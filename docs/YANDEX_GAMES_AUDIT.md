# Veymora Survivors — Аудит архитектуры и платформенной интеграции (Яндекс Игры)

## 1. Введение и цели аудита

Данный документ фиксирует архитектурный аудит и результаты устранения рисков интеграции проекта **Veymora Survivors** (версия **0.3**, Godot 4.6.2, WebGL2 / GL Compatibility, single-threaded) с платформой **Яндекс Игры**.

Цель интеграции: обеспечить стабильную работу игры в браузерах Desktop и Mobile (Android / iOS) внутри инфраструктуры Яндекс Игр при гарантированном сохранении 100% автономной работы в офлайн-режиме и Godot Editor без зависимостей от внешнего SDK.

---

## 2. Стандартизированная система статусов

В соответствии с требованиями к прозрачности и реалистичности контроля качества, для каждого компонента и требования зафиксирован статус из следующего перечня:

| Статус | Описание |
|---|---|
| `IMPLEMENTED` | Реализовано в коде проекта (GDScript / HTML / CSS / TSCN). |
| `AUTOMATED_TESTED` | Проверено автоматическими тестами проекта в headless-режиме (все 14 тест-сьютов). |
| `BROWSER_TESTED` | Проверено в локальном браузере через HTTP-сервер. |
| `YANDEX_TESTED` | Проверено в тестовой песочнице / iframe Яндекс Игр. |
| `CONSOLE_CONFIGURED` | Настроено в консоли разработчика Яндекс Игр (параметры, лидерборды, медиа). |
| `NOT_VERIFIED` | Ожидает проверки (требует загрузки черновика в консоль или прохождения модерации). |

## 4. Архитектурные детали ключевых подсистем

### 4.1. Инициализация и Loading API (P0.1)

Раньше вызов `LoadingAPI.ready()` мог произойти до полной инициализации сцен движка или зависнуть при долгом ответе JS-промиса `ysdk.getPlayer()`.

Решение:
1. В `YandexGamesBridge` введены раздельные флаги:
   - `is_sdk_initialized`: флаг готовности SDK платформы.
   - `is_game_ready`: флаг завершения инициализации стартовой сцены игры (`MainMenu._ready()`).
2. Метод `_check_and_send_loading_ready()` вызывает `ysdk.features.LoadingAPI.ready()` строго при совпадении обоих условий и взводит флаг `is_loading_ready_sent = true`, исключая повторные вызовы.
3. Добавлен глобальный аварийный таймер готовности (4000 мс в JS и 5.0 с в GDScript): если SDK отвечает с задержкой или падает, игра не блокируется и завершает цикл загрузки.
4. Запрос `getPlayer()` защищен `Promise.race()` с таймаутом в 2000 мс.

### 4.2. Сквозной цикл облачных сохранений (P0.2)

1. **Автоматическая синхронизация при запуске:**
   - После инициализации SDK мост запрашивает облачные данные.
   - Если данные получены, вызывается `SaveManager.merge_with_cloud(cloud_data)`.
   - Результат слияния немедленно сохраняется в локальное хранилище.
2. **Дебаунсинг изменений (1.5 сек):**
   - При изменениях прогресса вызывается `schedule_cloud_save()`, накапливающий изменения и предотвращающий троттлинг запросов к платформе.
   - При выходе из игры или завершении забега вызывается `flush_cloud_save()` для немедленной записи.
3. **Авторизация пользователя:**
   - В правом верхнем углу `MainMenu` размещен статус аккаунта и кнопка входа («Войти» / «Личный кабинет»).
   - При успешной авторизации происходит бесшовное слияние локального прогресса с облачным профилем игрока без перезапуска приложения.

### 4.3. Централизованная синхронизация Gameplay API (P0.3)

Синхронизация вызовов `gameplay_start()` и `gameplay_stop()` централизована в `YandexGamesBridge`:
- Подписка на сигналы `GameFlow.state_changed` и `PauseMgr.pause_state_changed`.
- Метод `reconcile_gameplay_state()` строго вычисляет целевое состояние:
  $$\text{target\_gameplay\_active} = (\text{GameFlow.current\_state} == \text{STATE\_PLAYING}) \land \neg \text{PauseMgr.is\_paused()}$$
- Вызовы `gameplay_start()` и `gameplay_stop()` происходят только при реальной смене состояния.
- В `GameFlowController` порядок смены состояния скорректирован: сначала обновляется состояние `current_state`, и только затем очищаются причины паузы.

### 4.4. Многофакторный менеджер паузы и управление звуком (P0.4)

- Управление паузой переведено на битовый реестр причин `PauseManager`:
  - `REASON_USER`: ручная пауза (Esc или кнопка на экране).
  - `REASON_BROWSER_FOCUS`: потеря фокуса вкладки браузера (`window.onblur`).
  - `REASON_PLATFORM`: внешняя пауза от платформы.
  - `REASON_ADVERTISEMENT`: показ полноэкранной рекламы.
  - `REASON_MODAL`: модальные окна (выбор улучшения, сундук, «Второй шанс»).
- При активной паузе любого типа мастер-шина приглушается (`AudioServer.set_bus_mute(0, true)`), а в `AudioManager` вызывается `stop_all_sfx()`, мгновенно обрывающий все звучащие звуковые эффекты.
- Звук возобновляется только тогда, когда сняты абсолютно все активные причины паузы. Пользовательские слайдеры громкости не затрагиваются.

### 4.5. Защищенные сессии рекламы (P0.6)

Для каждого показа рекламы генерируется уникальный `session_id`:
- Конечный автомат сессии: `IDLE` -> `PENDING` -> `OPENED` -> (`REWARDED`) -> `CLOSED` / `FAILED`.
- В JS-колбэки передается текущий идентификатор сессии. Колбэки от устаревших или повторных вызовов отбрасываются.
- При показе рекламы накладывается причина паузы `REASON_ADVERTISEMENT` и вызывается `gameplay_stop()`.
- По факту закрытия причина паузы снимается, и состояние геймплея согласуется заново.
- Награда «Второй шанс» начисляется строго при наличии подтвержденного события `onRewarded` в рамках активной сессии.

### 4.6. Локализация и паритет словарей (P1.7)

- `LocalizationManager` содержит полные словари переводов для русского (`ru`) и английского (`en`) языков.
- Реализован автоматический тест `test_localization_key_parity()`, проверяющий:
  1. Полное совпадение набора ключей в русском и английском словарях.
  2. Отсутствие пустых строк или заглушек.
- Устранены все зашитые русские строки в `ResultsScreen`, `ArchiveDialog`, `HUDController` и подсказках управления.
- Приоритет выбора языка:
  1. Ручной выбор игрока (`user_selected_language = true`).
  2. Язык платформы из `ysdk.environment.i18n.lang`.
  3. Дефолтный язык (`ru`).

## 5. Задачи для настройки в консоли разработчика Яндекс Игр

Следующие параметры должны быть сконфигурированы разработчиком в панели управления Яндекс Игр перед отправкой на модерацию:

1. **Таблица лидеров:**
   - **Техническое название:** `rift_explorers`
   - **Тип очков:** Числовой (целое число, `integer`)
   - **Направление сортировки:** По убыванию (чем больше очков, тем выше позиция)
   - **Десятичные знаки:** 0
2. **Рекламные форматы:**
   - Включить Interstitial (межстраничная реклама).
   - Включить Rewarded Video (реклама с вознаграждением для механики «Второй шанс»).
3. **Ориентация экрана:**
   - Альбомная (Landscape).
4. **Промо-материалы:**
   - Иконка 512x512 px.
   - Обложка 800x450 px (16:9).
   - Скриншоты геймплея в альбомной ориентации.
